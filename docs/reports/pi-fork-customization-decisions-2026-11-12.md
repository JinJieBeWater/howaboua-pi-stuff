## 1. Core 单行 agent 状态摘要

`328c4370`（11 月 1 日）把输入框上方的多行状态列表压缩成一行；`5c27e277`（11 月 5 日）补充 blocked agent 点名，并只在机器未全部连接时显示机器数量。直接目标是省终端纵向空间、突出需要处理的状态。

同一组三个 peer 的实际渲染函数输出，省略颜色：

上游：

```text
╭─ herdr peers 3 · 2/2 machines
│ ● local / qa blocked · project
│ ◉ remote / builder working · project
│ ✓ local / docs done · project
╰─
```

fork：

```text
agents · ● qa blocked · ◉ 1 working · ✓ 1 done
```

上游直接显示每个 peer 的名字、机器、状态和目录。fork 除 blocked 点名外主要显示状态数量。监控异常仍会另占警告行。

上游现在已过滤本会话监督的 workers，只显示 watched peers。探针确认：只有本会话 workers、无监控告警时，两版都不显示这块 widget。这缩小了原补丁目前的作用范围。

用户选择原文：**“跟进上游，撤掉这项补丁（建议）”**。

## 2. 成功的工具调用合成一行

`5c27e277` 的提交说明明确要求已完成记录合成一行。原显示会分别绘制调用和结果，目标可能重复，列表查询的结果标题又常常只有 done。

```text
上游创建成功：                  fork 创建成功：
agents spawn · explorer          agents spawn · qa · spawned
qa · spawned

上游列表查询：                  fork 列表查询：
agents list                     agents list · 3
done
```

这只影响成功、已完成、未展开的记录。运行中进度和展开后的任务/详细结果仍保留，不改变工具交给模型的结果。

同一提交包含的错误正文修复单独保留：上游自定义 renderer 可能把没有 details 的错误画成 done，fork 会展示真实错误；无效调用仍能显示尝试的 action/target 也属于错误诊断。恢复成功布局不需要撤掉这两项。

用户选择原文：**“成功布局跟进上游，保留错误修复（建议）”**。

## 3. 自动报告卡片的外观

这是 worker 自动发回完成或提问报告的卡片，与主动调用 agents 工具的结果行不同。`5c27e277` 去掉重复的 Herdr agent/local 前缀，使用状态图标，并把目录、workspace/tab 放到展开后，以缩短默认卡片。

按相同报告内容还原的示意：

```text
上游：
Herdr agent local / qa (t1) · finished
Workspace / Tab · /example/project

Response
检查完成，没有发现问题。

fork：
✓ qa · finished · t1
检查完成，没有发现问题。
```

上游更直接呈现来源，fork 更紧凑。元数据并未从记录中删除，也不改变模型收到的报告。这项与长文高度上限、问题是否默认显示可以分别决定。

用户选择原文：**“卡片外观跟进上游（建议）”**。

## 4. 长报告默认折叠为 16 个渲染行

`5c27e277` 用 `CollapsedResponse` 包住未展开的响应，超过 16 个终端渲染行时显示展开提示。目的是避免多个 worker 的长报告铺满对话。

例如 80 个屏幕行的响应，上游默认展示全部；fork 默认展示前 16 行及“另有 64 行”的展开提示。长文字因终端宽度发生的换行也计入上限。

展开后仍是完整响应，模型也收到完整内容；它不减少模型上下文。上游目前没有等价上限。

用户选择原文：**“跟进上游，默认显示完整报告”**。

## 5. 提问时不展开就显示问题正文

`5c27e277` 明确要求 blocked questions 在未展开时仍可见。上游会展示 blockedOn 或一般等待提示，但 `extensionMessages` 中的完整问题正文通常要展开后查看；fork 在 blocked/extension-message 卡片上直接显示这些消息。

如果 blockedOn 已经含有摘要，上游也能显示有用内容。区别是 fork 会额外保证具体问题正文默认可见。

这项不自动回答、不批准，也不改变消息传递。跟进上游后仍能展开查看和回答。

用户选择原文：**“跟进上游，需要时展开查看”**。

## 6. reply 的显式 blocking:true

`16f8492f`（11 月 6 日）解决的主要问题是：回答 worker 的问题后，reply 还等它完成后续长任务，控制者被占住。fork 改为默认收到语义送达回执就返回，并保留显式 `blocking: true` 的可选等待。

上游 1.0.0 已经实现主要修复。默认调用两版均是：

```text
worker 提问暂停 → reply 送达答案 → 控制者继续工作
                                   worker 后续结果后台报告
```

fork 的额外能力只是在原本会阻塞 worker 的扩展问题上选择等工作恢复并完成；当前实现等待结束仍主要返回送达回执，没有把 worker 最终工作正文带入该返回值。

撤掉额外参数不会恢复旧的默认阻塞，也不影响 spawn/assign 自己的 blocking 能力。取消等待后仍须抑制旧问题的正确性记录不是此项取舍的删除对象。

用户选择原文：**“跟进上游，去掉 reply 的额外等待参数（建议）”**。

## 7. 普通模式的主动并行分工提示

`f8fbc113`（11 月 6 日）希望独立范围不必等用户明确要求就主动委派。fork 普通模式提示“小任务自己做，独立范围主动并行”；general profile 帮助也从“仅要求或编排时使用”改为“独立实施范围”。

上游普通模式是“正常工作，有用或用户要求时委派”。进入显式编排模式后，两版都已经要求分工。

这是模型建议，不是后台调度器。保留可能增加 agent 和协调成本，但不保证更快。恢复上游仍允许有用时委派，且不会覆盖个人、项目或当前会话中其他更高优先级的分工要求。

用户选择原文：**“分工提示跟进上游（建议）”**。

## 8. Shepherdr／Notes 启动打包

`1ede1a6f`、`32b7b21b`（11 月 1 日）把包内模块打成较少的 Node ESM 文件，减轻启动时 jiti 对 TypeScript 模块图的加载/解析成本。运行 Pi 的仍是 Node，Bun 用于生成发布产物。

```text
上游：启动 → index.ts → jiti 解析较多内部模块
fork：安装/打包 → dist/*.js；启动 → 已生成的 JavaScript
```

历史 Pi 1.4.0 报告的交错五次样本：两包打包与 Browser 懒加载整组补丁，使启动中位数从 4537.6 ms 降至 2467.4 ms，约减少 46%。该历史不能拆作单包收益，也不能代表当前 Pi 1.5.2；上游 Notes 现在按需初始化，收益可能变化。

维护成本是 65 行打包脚本、两包入口/exports/prepack、根 install 配套，以及打包后的资源路径。上次 Notes 上游移动源码目录就需要修改打包入口。撤掉不会卸载扩展，但可能增加当前启动时间。

用户选择原文：**“先测当前启动收益，再决定（建议）”**。

实测后分别选择：**“保留 Shepherdr 打包（建议）”**、**“保留 Notes 打包（建议）”**。

## 9. Browser 执行后端懒加载

`84933b1d`（11 月 1 日）把 runtime/CDP/操作执行器的模块加载延迟到首次真正操作，help 直接返回，不加载后端。

```text
上游：启动 → 注册工具并导入后端；首次操作 → 执行
fork：启动 → 注册工具；首次操作 → 导入后端 → 执行
```

上游构造 runtime 本身不会立即打开 Chrome；补丁主要移后模块导入成本。未使用浏览器的会话可能更快，首次操作可能更慢。fork 多维护加载 Promise、轻量代理和关闭处理，改动约二十多行。

它与两包打包独立，也参与了历史整组收益；本轮补做了下节记录的单项对照。

用户选择原文：**“一起测当前收益，再决定（建议）”**。

实测后选择：**“保留 Browser 懒加载（建议）”**。

## 支持最终性能决策的数据

数据来自本机 Pi 1.5.2 的隔离 RPC 启动；每条件预热后正式三次交错采样，没有模型请求。

| 优化 | 观察到的收益 | 适用范围 |
| --- | ---: | --- |
| Shepherdr 打包 | 扩展加载阶段约少 500 ms | 同入口/工厂的受控配置；没有连接真实 Herdr Core |
| Notes 打包 | 初始化控制组 RPC 就绪约少 254 ms | 移除 Codex Conversion 后确认 Notes 激活；不等于日常完整配置的精确收益 |
| Browser 懒加载 | 扩展加载阶段约少 153 ms | 当前 deferred 曝光路径；未测首次真实操作成本 |

Notes 在包含 Codex Conversion 的完整 RPC 条件中没有完成初始化，因此不能用该条件的约 3 ms 差异判断 Notes 日常“没有收益”。用户知悉这一限制后选择保留。33 个保留的测量样本均成功，原始数值已由父 agent 复核；完整方法、范围和原始数据见 [启动测量报告](pi-fork-startup-benchmark-2026-11-12.md)。
